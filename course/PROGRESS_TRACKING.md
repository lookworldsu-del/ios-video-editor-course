# 章节学习仪表盘协议

`course/PROGRESS.md` 记录 42 章的粗粒度状态；`course/progress/chapter-NN.md` 记录当前学习轮次中某一章的微目标、证据和小步进度。`course-base` 只保存零进度表和仪表盘模板，真实状态只属于当前 `learning/round-*` 分支。

仪表盘的目标是让学习者随时知道“已经真正掌握什么、现在只做什么、完成后解锁什么”，而不是用老师讲过多少内容制造虚假百分比。

## 状态定义

| 状态 | 含义 | 是否计入完成 |
|---|---|---:|
| `[ ]` | 尚未开始 | 否 |
| `[~]` | 当前唯一小目标，正在学习 | 否 |
| `[!]` | 学过但证据不足，需要回顾 | 否 |
| `[x]` | 已通过复述、计算、实验或代码证据验证 | 是 |

进度百分比只按 `[x] / 全部微目标` 计算，由 `scripts/show-learning-progress.sh` 生成，禁止手填或为了鼓励而虚增。

## 主教师工作流

开始或继续章节教学时：

1. 读取 `course/PROGRESS.md` 和当前章 `course/progress/chapter-NN.md`。
2. 如果进度文件不存在，按 `course/progress/TEMPLATE.md` 创建 8～14 个可验证微目标。
3. 每个微目标控制在约 20～60 分钟，只描述一个清晰能力，并包含验收证据和解锁能力。
4. 同一时刻最多一个 `[~]`；开始第一个微目标时，把本章在 `course/PROGRESS.md` 中改为 `[~]`。
5. 教授一个小节并等待学习者反馈。老师讲完、子代理返回或代码自动生成，都不能直接算完成。
6. 学习者给出证据后，由主教师决定将当前目标改为 `[x]`、`[!]` 或继续保持 `[~]`，并在“验收证据”中写一句可复查事实。
7. 每次教学回复末尾运行 `scripts/show-learning-progress.sh NN`，把输出的简版仪表盘展示给学习者，并只给出一个下一小目标。
8. 所有普通微目标完成后才能进入 `CNN-GATE`；只有 `examiner` 给出通过结论，最终门槛才能标记 `[x]`。
9. 仪表盘达到 100% 后，主教师才能把 `course/PROGRESS.md` 中本章改为 `[x]`。

新 Codex 任务必须继续读取同一个章节进度文件，不得重新估算、清空或根据聊天记忆猜测进度。

## 多角色边界

- 主教师是进度状态的唯一维护者和最终决定者。
- `concept_teacher` 可以根据学习者回答建议 `[x]`、`[!]` 或继续 `[~]`，但不得修改文件。
- `ios_coach` 和 `reviewer` 提供实现、测试和评审证据，不直接改变进度。
- `examiner` 只负责最终综合验收，不维护百分比。
- 不新增专门的进度子代理；计数和展示由确定性脚本完成，避免代理之间对学习状态产生分歧。

## 文件约束

- 文件名必须是 `course/progress/chapter-NN.md`，章节号补齐两位，例如 `chapter-02.md`。
- 微目标 ID 必须唯一，格式为 `CNN-01`、`CNN-02`；最终验收使用 `CNN-GATE`。
- 表格列顺序必须保持为“ID、状态、小目标、验收证据、解锁能力”，供展示脚本解析。
- 表格单元格内不要使用竖线字符 `|`，避免破坏脚本解析。
- 学习分支保留已经完成章节的仪表盘，不要在进入下一章时覆盖旧文件。
